# 虛擬新傳說（Virtual Legends）企劃

2026-10-30，Claude（轉蛋 RPG 規劃工作階段）寫，使用者看過並確認方向與 M1 範圍。

名稱：**虛擬新傳說**（英文 **Virtual Legends**，repo `YuutaTsubasa/VirtualLegends`，公開）。Virtual 系列第六款，原創的回合制轉蛋 RPG。下面用「本作」代稱。

## 已確認的三個決定（使用者 2026-10-30）

| 項目 | 決定 | 影響 |
| --- | --- | --- |
| 收不收真錢 | **不收**，只用遊戲內貨幣轉蛋 | 不接商店付款、不驗收據；機率仍然公開（之後要收費時直接沿用） |
| 玩家互動 | **PvE＋非同步 PvP** | 打別人存的防守隊伍（由 AI 操作）；沒有即時對戰、沒有公會、沒有聊天 |
| Server | **輕量 Server** | 帳號、轉蛋、貨幣、庫存、戰鬥結算驗證、PvP 防守隊伍與排名；不跑即時戰鬥 |

## 1. 核心循環

```
打關卡／每日任務／PvP ──► 拿到「星屑」（轉蛋貨幣）、經驗素材、突破素材
        ▲                                │
        │                                ▼
  更強的隊伍去打更難的關卡 ◄── 養成 ◄── 轉蛋抽「衣裝」
```

- **轉蛋**：抽到的是「某位角色的某套衣裝」（例：小翠・麻將館制服、小翠・夏日祭典）。同一位角色可以有很多套衣裝，每套是獨立的可戰鬥單位，技能與屬性不同。
- **養成**：衣裝升級（經驗素材）、突破（重複抽到同一套，或通用突破素材）、技能升級；另外每位**角色**有共用的「羈絆」（見 §2），練任何一套衣裝都會加。
- **關卡**：主線章節（劇情＋戰鬥）、每日素材關、PvP。沒有體力制（不收錢就沒有理由限制玩的時間），改用「每日首次通關獎勵」控制貨幣產出。

貨幣只有兩種，避免一開始就太複雜：

| 貨幣 | 用途 | 來源 |
| --- | --- | --- |
| 星屑 | 轉蛋（一抽 100、十抽 1000） | 首次通關、每日任務、成就、PvP 每週結算 |
| 金幣 | 升級、技能升級、突破手續費 | 所有關卡 |

## 2. 角色與衣裝的資料模型

系列已有十一位角色（小翠、月華、阿明、糖糖、小春、蘭姐、蒼牙、金爺、雷歐、阿烈，隱藏角色阿翼），id、名字、簡介、配色、半身像（五種表情）在五款都一樣。本作沿用，**角色是身分，衣裝是戰鬥單位**。

```
Character（系列共通，唯讀）
  id, name, intro, colors, lines（台詞）, portraits
    │ 1
    │
    │ N
Costume（本作的遊戲資料，放 repo 的 data/）
  id: "xiaocui.festival"
  character_id: "xiaocui"
  name: "夏日祭典"
  rarity: 3 | 4 | 5
  suit: 萬 | 筒 | 條 | 字           ← 屬性（見 §3）
  role: 攻擊 | 守護 | 支援 | 妨礙
  base_stats: { hp, atk, def, spd }
  growth: 每級成長
  skills: [普攻, 技能, 大招]（id，技能內容在 data/skills）
  art: { portrait, battle_sprite, card }（依畫風取圖）
  released_in: 卡池版本

UserCostume（Server 的資料庫，每位玩家一筆／一套）
  user_id, costume_id
  level, exp, ascension(0–5), skill_levels[3]
  obtained_at

UserCharacter（Server，每位玩家每位角色一筆）
  user_id, character_id
  bond_exp, bond_level         ← 羈絆：練該角色的任何衣裝都會加
```

規則：

- **一隊四人，同一位角色只能上一套衣裝**（不會出現兩個小翠）。
- **羈絆**：角色層級的共用成長。羈絆等級給該角色所有衣裝小幅全能力加成、解鎖劇情與台詞。讓「同一個角色不同衣裝」有意義：抽到第二套小翠，不是從零開始。
- **重複抽到**同一套衣裝：轉成突破（最多 5 次）；滿突破後轉成羈絆經驗與星屑碎片。
- 稀有度三級：★3（每位角色的「麻將館制服」——直接用現有半身像，成本最低）、★4、★5。
- 衣裝、技能、敵人、關卡、卡池都是 repo 裡的資料檔（JSON／RON），Client 和 Server 讀同一份；Server 以 repo 的版本為準，Client 版本太舊時要求更新。

## 3. 戰鬥系統草案：「牌氣」回合制

為了跟市面上的回合制轉蛋 RPG 做出區隔，戰鬥資源借用系列的根——**麻將館**。

- **場上**：我方四人 vs 敵方 1～5 隻，分波次。
- **回合**：每回合雙方輪流；每回合開始，我方從牌山摸 **3 張「牌氣」**（萬／筒／條／字，字牌較稀有）放進共用手牌（上限 8 張）。
- **指令**：每回合我方**每人各行動一次**，順序由玩家自己排（不是速度條）。每人可以選：
  - 普攻：不花牌，打出時「加 1 張自己屬性的牌」。
  - 技能：花 1～2 張**自己屬性**的牌。
  - 大招：花 3 張，且必須組成**順子**（同花色連號，例 二三四萬）或**刻子**（三張一樣）；刻子效果更強。字牌可以當萬用牌，但大招威力降一級。
  - 速度（spd）不決定順序，而是決定**敵人的行動插在第幾位**：敵人比我方某人快，就會在他之前出手。
- **屬性相剋**：萬 → 條 → 筒 → 萬（剋的一方傷害 +30%、被剋的一方 −20%）；字牌屬性（東南西北中發白歸成「字」）不剋也不被剋，但大招能用任何花色的牌。
- **合技**：同一回合裡，四人依序打出的牌剛好湊成「一組順子＋一組刻子」，回合結束時觸發全隊合技（類似「聽牌」演出）。這是本作的招牌爽點，需要排順序的策略。
- **敵人**也有手牌與屬性，玩家看得到它下回合可能的大招（「敵方聽牌」提示），可以先打掉它的牌（妨礙型技能「吃」、「碰」別人的牌）。
- **自動戰鬥**、二倍速：AI 用同一套規則排順序。

**實作**（`crates/legends-core`，2026-10-30）照上面的規則，另外定了：

- 我方一次送一個指令（誰、做什麼、花哪幾張牌），送出時就檢查。輪到他之前，比他快的敵人如果偷走了要花的牌，這次行動退回普攻（`Fizzle` 事件）。
- 技能的牌：自己屬性，或字牌代替；字屬性的衣裝可以花任何牌。
- 敵人每回合摸 1 張（最多 3 張，滿了丟最舊的），三張組成順子或刻子就「聽牌」（`Ready` 事件），輪到它時放大招。
- 守護型活著時，敵人一半的機率打他。
- 等級上限看突破：0 突破 20 級，每次 +8，滿突破 60 級。
- 30 回合打不完算輸。
- 傷害 = 攻擊 × 威力% × 200／(200 + 防禦) × 屬性 × 浮動 95～105%，全部整數運算。

**決定性**：戰鬥引擎是 Rust、無外部狀態、所有亂數來自 Server 發的種子（`battle_seed`），同一組（隊伍快照、敵人資料、種子、玩家指令紀錄）一定得到同一個結果。Server 就是靠這點重算、驗證。

## 4. Client–Server 分工

### Server 決定（權威）

| 事情 | 怎麼做 |
| --- | --- |
| 帳號 | 第一版用**訪客帳號**：第一次開啟時 Server 發帳號 id＋裝置金鑰；另有「繼承碼」換裝置。不做密碼（之後要的話接 Google／Apple 登入） |
| 轉蛋 | Server 用 `crypto.getRandomValues` 抽，寫入庫存與抽卡紀錄後才回傳結果；保底計數存在 Server；卡池與機率表是 repo 的資料檔，遊戲內公開每張卡的機率 |
| 貨幣、庫存、養成 | Client 只送「我要把 A 升到 30 級」，Server 檢查素材、扣除、寫入，回傳新狀態 |
| 戰鬥結算 | 開打前 Client 申請「戰鬥票」：Server 記下關卡、隊伍快照、`battle_seed`。打完 Client 送指令紀錄，Server 用**同一份 Rust 引擎（WebAssembly）重算**，結果一致才發獎勵 |
| 非同步 PvP | 玩家設定防守隊伍（Server 存快照）。挑戰時 Server 配對對手、發戰鬥票（含對方快照、種子）；對方由 AI 操作，Server 重算後更新積分。每週結算排名與獎勵 |
| 每日重置、任務、首次通關 | Server 時間為準（台灣時間凌晨 4 點重置） |

### Client 負責（呈現）

- 戰鬥的即時演出：用同一份引擎在本機跑（網頁版 WebAssembly、App 也一樣），畫面、動畫、音效、FM 音樂。
- 抽卡演出（結果已經由 Server 決定，Client 只是演）。
- 選單、隊伍編成、劇情、圖鑑、設定（語言、音量、畫風、手把）。
- 只在本機存：設定、快取的資料檔。**不存任何會影響獎勵的狀態**。
- 離線時可以玩「練習模式」（不發獎勵），其他都要連線。

### 防作弊的底線

- Client 改數值、改引擎 → 重算結果不同 → 不發獎勵。
- 同一張戰鬥票只能結算一次；票有效期限（例 30 分鐘）。
- 戰鬥重算吃 CPU：先量測一場的 WebAssembly 重算時間。Cloudflare Workers 免費方案每次請求只有 10 ms CPU，超過的話用付費方案（每月 5 美元，30 秒 CPU）——要收費前先問使用者。

## 5. 技術選型

盡量沿用系列：

| 部分 | 選擇 | 沿用自 |
| --- | --- | --- |
| Client | Tauri v2＋Svelte 5＋Vite 6；網頁版＋六平台（Android 為主） | 五款共通 |
| 戰鬥引擎 | Rust crate `legends-core`，`wasm-pack` 編成 WebAssembly，Client 與 Server 共用 | 四款的 `*-core`／`*-wasm` 結構 |
| Server | Cloudflare Workers（JS 入口＋載入 `legends-core` 的 wasm）＋**D1**（SQLite）存帳號、庫存、抽卡紀錄、PvP | 系列的配對服務已在 Cloudflare Workers，帳號、wrangler 都已設定 |
| 資料檔 | repo 的 `data/`（衣裝、技能、敵人、關卡、卡池），建置時同時打包進 Client 與 Server | — |
| 音樂、音效 | VirtualCore 的 FM 音源與播放器 | VirtualCore |
| 多國語言 | VirtualCore `i18n/lang.js`，中／英／日 | VirtualCore |
| 手把 | VirtualCore `input/controls.js` | VirtualCore |
| 畫風 | 五種畫風的切換機制沿用；**衣裝新圖第一版只畫 90 年代版一種**，其他畫風沒有圖時自動用 90 年代版（現有 `style-assets.js` 就是這樣） | 五款共通 |
| CI／發版 | VirtualCore 的 `build-apps.yml`、`pages.yml`；Server 另加 `wrangler deploy` workflow | VirtualCore |
| 畫面方向 | **橫向** 960×540 基準（跟系列一致，掌機也好用） | 五款共通 |

不需要的共通模組：`p2p.js`、signal worker、`virtual-room`、`virtual-lan`（沒有即時連線與區網開房）。

慣例：dev 埠 **1425**、`localStorage` 前綴 **`vl_`**（只放設定，不放存檔）、crate 前綴 `legends-`、預設分支 `main`。

## 7. 第一個可玩里程碑（M1）

目標：**自己和少數朋友能從開帳號玩到第一章結束，抽卡、養成、戰鬥結算都經過 Server**。網頁版＋Android APK。

包含：

- **衣裝 15 套**：十位角色的★3「麻將館制服」（用現有半身像，阿翼仍是隱藏、不進卡池）＋★4 三套＋★5 兩套（新畫，只畫 90 年代版）。
- **轉蛋**：一個常駐卡池，單抽／十連，★5 保底（例：80 抽必出），遊戲內公開機率與保底計數。
- **養成**：升級、突破、羈絆；技能升級先不做。
- **戰鬥**：牌氣回合制完整規則（摸牌、技能、順子／刻子大招、屬性相剋、合技、敵方聽牌提示）、自動戰鬥、二倍速。
- **關卡**：第一章 10 關＋魔王，簡短劇情（文字＋半身像，沿用台詞風格）；一個每日金幣關。
- **Server**：訪客帳號＋繼承碼、轉蛋、庫存、養成、戰鬥票與重算驗證、首通與每日獎勵。
- **語言**：中文完成；英、日的字串結構先就位（翻譯在 M1 之後、對外公開前補）。
- **音樂**：FM 曲 3 首（標題、戰鬥、魔王）。

**不包含**（M2 以後）：非同步 PvP（防守隊伍、配對、積分、每週排名——Server 資料表 M1 先預留）、裝備、技能升級、限定卡池、其他四種畫風的新衣裝圖、Google／Apple 登入、iOS 實機。

M1 驗收：

1. `cargo test`：戰鬥引擎決定性（同輸入同結果）、Client 與 Server 用的 wasm 結果一致。
2. 改 Client 數值後結算 → Server 拒絕。
3. 抽 1000 次的統計接近公開機率；保底正確。
4. 網頁版與 Android APK 從開帳號打到第一章魔王。

### M2 草案：非同步 PvP

防守隊伍設定、依積分配對、挑戰（每日次數）、Server 重算更新積分、每週結算星屑、排行榜。之後再考慮限定卡池、裝備。

## 風險

- **美術量**：衣裝是轉蛋遊戲的核心賣點，每套要半身像（五表情）＋戰鬥圖＋卡面，五種畫風乘下去很大。M1 只畫一種畫風、★3 用現有圖。
- **Workers CPU 限制**：已量測（2026-10-30，`legends-core` 的 `replay_cost`）：魔王戰 77 個指令原生重算約 0.065 ms、讀資料約 0.03 ms；wasm 慢幾倍也遠低於免費方案的 10 ms。接上 Worker 後再實測一次。
- **平衡**：沒有收費壓力，但 PvP 一上線就需要平衡；M1 先把數值放資料檔、方便調整。
- **原創性**：戰鬥（牌氣）、成長（羈絆）、世界觀都以系列自己的麻將館為根，不照搬任何現有遊戲的系統、介面或名稱。
