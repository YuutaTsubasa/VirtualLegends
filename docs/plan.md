# 虛擬新傳說（Virtual Legends）企劃

2026-10-30，Claude（轉蛋 RPG 規劃工作階段）寫。第一版（「牌氣」麻將戰鬥）使用者看過後覺得跟原本的方向差太多，同日改成這一版：**回到回合制角色收集 RPG 這個類型的核心**，拿掉麻將元素，外觀改用 bluebolt-ui。

名稱：**虛擬新傳說**（英文 **Virtual Legends**，repo `YuutaTsubasa/VirtualLegends`，公開）。Virtual 系列第六款，原創的回合制轉蛋 RPG。

**原創性的界線**：這個類型共通的機制（速度決定的行動條、每人三招與冷卻、屬性相剋、增減益、反擊、連攜、裝備套裝）可以用；**不照抄**任何一款現有遊戲的系統名稱、數值、介面版面、美術或劇情。下面的名稱與數字都是本作自己定的。

## 1. 五個核心設計問題

本作每個系統都要回答下面其中一題，回答不了的就不做。

| 問題 | 本作的答案 | 對應系統 |
| --- | --- | --- |
| **為什麼要收集新角色？** | 每個角色帶來**新戰術**：不同屬性、隊伍定位（攻擊／守護／支援／妨礙）和機制（加速隊友、延遲敵人、反擊、連攜、淨化、護盾）。同一位系列角色的不同版本，玩法差很多（例：小翠・日常是單體輸出，小翠・夏日祭典是全隊加速） | §3 角色、§4 戰鬥 |
| **為什麼要培養角色？** | 數值成長（等級、突破、羈絆）、**技能強化**（每級改變效果，不只加傷害）、**裝備構築**（主屬性、副屬性、套裝效果決定這個角色在隊裡負責什麼） | §5 養成 |
| **為什麼要思考隊伍編成？** | 角色互補（誰開場加速、誰收尾）、**行動條資源循環**（加速／延遲／接棒）、**連攜觸發**（羈絆組合、屬性共鳴） | §4.4 隊伍協同 |
| **為什麼每場戰鬥不一樣？** | 敵方機制（蓄力大招要在發動前打斷、護盾、階段轉換、召喚）、**行動順序**隨速度與推條變化、**環境條件**（每關的場地效果） | §4.5 敵人與環境 |
| **為什麼值得重複遊玩？** | 同一關有**不同隊伍解法**、**挑戰模式**（每日素材關、魔王討伐、之後的 PvP）、**策略優化**（更少回合、無傷、特定條件的星等評價） | §6 關卡與模式 |

## 3. 角色的資料模型

系列已有十一位角色（小翠、月華、阿明、糖糖、小春、蘭姐、蒼牙、金爺、雷歐、阿烈，隱藏角色阿翼），id、名字、簡介、配色、半身像在五款都一樣。**系列角色是身分，抽到的角色（某個版本）是戰鬥單位。**

```
Character（系列共通，唯讀）：id, name, intro, colors, portraits

Costume（本作資料 data/costumes.json；程式內部名稱，畫面上叫「角色」）
  id: "xiaocui.festival", character: "xiaocui", name: "夏日祭典"
  rarity: 3 | 4 | 5
  element: blaze | tide | gale | dawn | dusk      ← 屬性（§4.2）
  role: attacker | guardian | support | disruptor
  base / growth: hp, atk, def, spd, crit, crit_dmg, hit, resist
  skills: [s1, s2, s3] ＋ passive（可選）
  bonds: ["yuehua", ...]                          ← 羈絆組合（§4.4）
  art: { portrait, battle, cutin }

UserCostume（Server）：level, ascension(0–5), dupes, skill_levels[3]
UserCharacter（Server）：bond_exp, bond_level      ← 練任何一個版本都會加
UserGear（Server）：裝備（§5.3）
```

- 一隊四人，同一位系列角色只能上一個版本。
- 稀有度三級：★3 是每位角色的「日常」版本（直接用現有半身像，原本叫「麻將館制服」，拿掉麻將後改名）、★4、★5。
- 重複抽到同一個版本 → 突破次數（最多 5）→ 滿了換星屑與羈絆經驗（沿用現有 Server 規則）。
- 所有遊戲資料都是 repo 的 `data/*.json`，Client 和 Server 讀同一份。

## 4. 戰鬥系統：行動條回合制

### 4.1 行動順序

- **場上**：我方四人 vs 敵方 1～5 隻，分波次。
- **行動條**：每個單位有一條 0～1000 的行動值，每一刻依速度增加；先到 1000 的出手，出手後歸零。畫面上方的**時間軸**顯示接下來誰會出手、大約多久。
- **推條**：技能可以「加速」（我方行動值 +X%，例：+25% 讓隊友馬上接著動）或「延遲」（敵方行動值 −X%，把敵人的大招往後推）。這是本作最核心的決策：**誰先動、在誰之前動**。
- **接棒**（本作的隊伍資源）：全隊共用 0～5 格的「聲援」，每次我方出手 +1。輪到某人時可以花 3 格指定一位隊友**緊接著出手**（不管他的行動值）。用來把增益和爆發串在同一個時機，或在敵人蓄力完成前搶先打斷。

### 4.2 屬性

五種屬性，三個循環相剋加兩個互剋：

```
焰 blaze → 嵐 gale → 潮 tide → 焰        曉 dawn ⇄ 暮 dusk
```

- 剋：傷害 ×1.3，效果命中 +15%。被剋：傷害 ×0.8，有 15% 機率擦傷（傷害減半、不附帶效果）。
- 曉、暮互剋，彼此都是「剋」；對三屬性沒有相剋。★5 才有曉／暮。

### 4.3 技能、效果、觸發

- **每人三招**：S1 普攻（無冷卻）、S2（冷卻 2～4 回合）、S3 大招（冷卻 4～6 回合）；可另有被動。冷卻以「自己的回合」計，所以加速也會加快冷卻循環。
- **技能時機**是第二個核心決策：大招現在放還是等增益、等敵人破盾、等連攜隊友就位。
- **效果**（Effect System）：傷害、治療、護盾、增益（攻擊↑、防禦↑、速度↑、暴擊↑、免疫）、減益（攻擊↓、防禦↓、速度↓、命中↓、灼燒、暈眩、挑釁、封印技能、阻止回復）、淨化、驅散、推條。減益要比**效果命中 vs 效果抵抗**。
- **觸發**（Trigger System）：
  - **反擊**：被打時有機率（或增益期間必定）用 S1 回擊。
  - **連攜**：隊友攻擊時，有連攜條件的角色跟著用 S1 打同一個目標。
  - **追擊**：條件達成（目標低血量、目標有某減益、我方暴擊）時自動追加一擊。
  - **被動**：回合開始、受傷、隊友倒下、敵人死亡等時機觸發。
  - 觸發產生的行動**不會再觸發連攜**（避免無限連鎖），反擊不會被反擊。

### 4.4 隊伍協同

- **羈絆組合**：資料裡寫好系列角色之間的關係（例：小翠＋月華、阿明＋蒼牙）。組合同隊時，連攜機率提高、各自的連攜台詞會出現。這是系列世界觀能給本作的獨有東西。
- **屬性共鳴**：隊伍裡同屬性 2 人／3 人時給小幅加成（例：焰 2 人攻擊 +5%），鼓勵也懲罰偏重同一屬性。
- **定位分工**：守護型被打的機率較高、常帶反擊與護盾；支援型負責推條、治療、淨化；妨礙型負責延遲、減益；攻擊型負責收尾與追擊。

### 4.5 敵人機制與環境

- **蓄力**：魔王把大招掛在時間軸上（「3 回合後發動」），玩家要延遲、暈眩，或在它之前打破護盾。
- **護盾／破盾**：護盾期間減傷，破盾後暈眩一回合——讓「這一刻集火」有意義。
- **階段**：血量降到某個比例換模式（換技能、召喚、全場效果）。
- **環境條件**：每一關可以有場地效果，例：「狂風：所有人速度 +15」「烈日：焰屬性攻擊 +10%、潮屬性 −10%」「迷霧：命中 −20%」。同一隊在不同環境打法不同。
- 敵人用同一套技能、效果與觸發系統，只是由 AI 選技能與目標。

### 4.6 引擎架構（`crates/legends-core`）

```
Combat Ruleset（可替換的戰鬥規則；第一個是「行動條」，之後可加時間軸、卡牌等變體）
   ├─ Scheduler        決定誰能行動（行動值、接棒、蓄力的時機）
   ├─ Action Resolver  解析技能與目標（指令驗證、目標選擇、AI）
   ├─ Effect System    傷害、治療、護盾、增減益、推條
   ├─ Trigger System   反擊、連攜、追擊、被動
   ├─ Resource System  冷卻、聲援、技能的特殊資源
   └─ Battle State     角色與戰場狀態（含環境）
            │
Deterministic Simulation Core
   事件佇列、亂數種子（SplitMix64）、狀態變更、戰鬥紀錄、重播與摘要
```

- **決定性**沿用現有做法：全部整數運算、亂數只來自 Server 發的種子、同一組（隊伍快照、關卡、種子、指令紀錄）一定得到同一個結果；Server 用同一份 wasm 重算驗證。
- 指令只有「誰（目前輪到的人）、哪一招、目標、要不要接棒給誰」，所以指令紀錄很短。
- 所有規則數字（冷卻、推條比例、相剋倍率、共鳴）放資料檔，不寫死在程式。

## 5. 養成

### 5.1 數值成長

沿用現有實作：等級（練習筆記＋金幣，上限看突破：0 突破 20 級、每次 +8、滿 60 級）、突破（重複角色＋金幣）、羈絆（系列角色共用，每級全能力 +1%，最多 10 級）。

### 5.2 技能強化

- 每招有 2～5 級，用技能書＋金幣升。
- 每一級寫明改變了什麼：**不只是傷害 +5%**，而是像「推條 +10% → +20%」「冷卻 4 → 3」「增益持續 2 → 3 回合」「附加防禦↓」。讓強化本身改變打法。

### 5.3 裝備

- 每人四格：**武器**（主屬性固定攻擊）、**護具**（固定防禦或 HP）、**飾品**、**徽章**（後兩格主屬性隨機：速度、暴擊、暴擊傷害、效果命中、抵抗、攻擊％、HP％…）。
- 稀有度三級（普通／精良／傳說），副屬性 2～4 條；強化 +0～+12，每 +3 新增或提升一條副屬性。
- **套裝**：同一套 2 件或 4 件觸發效果，例：「疾風（2）速度 +10%」「連攜（4）連攜機率 +20%」「堅守（4）被打時 25% 反擊」「專注（2）效果命中 +15%」。套裝讓同一個角色可以配成不同用途。
- 裝備從關卡掉落（**Server 用 crypto 亂數決定掉落**，跟轉蛋一樣），可以賣成金幣、拆成強化石。
- 裝備會進戰鬥票的隊伍快照，Server 重算時用快照裡的最終能力值。

## 7. 戰鬥演出與介面

- **戰鬥畫面**：2D 橫向對峙，我方四人在左、敵人在右。角色是**全身站姿圖**，待機時輕微呼吸；出手時衝刺、受擊閃白、跳字（傷害／暴擊／治療／效果名）、倒下淡出。
- **大招特寫**：用角色半身像做斜切滿版的進場（bluebolt-ui 的斜切、擦入、掃光動態），配技能名。
- **時間軸**：上方一條，顯示接下來的出手順序（頭像），推條時頭像會滑動；敵人的蓄力大招也標在上面。
- **介面風格**：用 **bluebolt-ui**（藍・白・黃・黑 HUD）：大廳用巨大階梯選單、角色列表用選擇卡、能力值用巨大外框數字；遊戲畫面另外依本作需要加元件，通用的元件回饋到 bluebolt-ui（另開 PR、打新 tag）。
- 自動戰鬥、2 倍速、撤退。手把操作（VirtualCore `input/controls.js`）。

**美術流程**（2026-10-30）：用 Codex CLI 的圖片生成（`codex exec`，附上系列半身像當角色參考）畫進 `art-inbox/`（不進 git），挑過後用 `python scripts/import-art.py` 轉成 webp 放進 `src/assets/art/`；`src/lib/art.js` 自動找圖，沒有就退回系列半身像。目前有：各版本半身像（四表情）、戰鬥全身圖（待機＋攻擊兩張，動作用 CSS 做呼吸、衝刺、受擊）、8 種怪物、3 張戰鬥背景、標題與大廳背景、App 圖示。大招動畫之後可能由使用者另外生成。

## 8. Client–Server 分工

沿用已完成的 Server（`workers/api`），只加裝備與技能強化：

| 事情 | 怎麼做 |
| --- | --- |
| 帳號 | 訪客帳號（只存裝置金鑰的 SHA-256）＋繼承碼 12 字、7 天 |
| 轉蛋 | ★5 3%、★4 15%、★3 82%，80 抽保底 ★5、十連保底 ★4；Server 用 crypto 亂數 |
| 養成 | 升級、突破、技能強化、裝備穿脫／強化／販賣，都由 Server 檢查與扣素材 |
| 戰鬥結算 | 開打前發戰鬥票（關卡、隊伍快照含裝備、種子），打完 Client 送指令紀錄，Server 用同一份 wasm 重算，一致才發獎勵與掉落 |
| 併發 | 每個請求一個 D1 batch（交易），`users.rev` 樂觀鎖 |

Client 只負責呈現：本機跑同一份引擎做演出；本機只存設定（`vl_` 前綴），不存會影響獎勵的狀態。

## 風險

- **美術量**：全身戰鬥圖 15 張是 M1 最大的工作量。先用半身像裁切當替身把戰鬥做完，圖到了再換。
- **規則複雜度**：觸發系統容易出現無限連鎖或順序爭議，所以在 §4.3 先定「觸發不再觸發連攜、反擊不被反擊」，並為每條規則寫測試。
- **Workers CPU**：舊引擎重算約 0.065 ms；新引擎事件更多，重寫後重新量測（免費方案每次 10 ms）。
- **平衡**：數字全部放資料檔，`balance_table` 測試印出每關用預設隊伍的勝率與回合數。
